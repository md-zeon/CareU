## Minor
### 🟡 `can()` hint checks trigger denial logging side effects, `lib/authz/guards.ts:66`
**Problem**: `can()` delegates to `requirePlatformPermission`/`requireShopPermission`, which call `logDenial` on every non-allow decision. Spec 0002 defines `can` as a non-throwing check for UI hints that shares the same evaluator as guards.
**Why it matters**: Using `can()` for UI visibility or hints can emit denial logs for normal rendering paths rather than actual protected-operation attempts, adding noise to observability.
**Suggested fix**: Route `can()` through a shared evaluation path without denial logging, while keeping denial logging on enforcing guard entry points.

### 🟡 Login redirect base URL is constructed inconsistently, `lib/authz/guards.ts:89`, `app/api/authz/roles/route.ts:12`
**Problem**: `routeDecisionResponse` builds login redirects from `process.env.BETTER_AUTH_URL || "http://localhost:3000"`, while `app/api/authz/roles/route.ts` builds redirects from the incoming request origin.
**Why it matters**: Divergent redirect-base logic can cause inconsistent behavior across environments or future call sites that use the shared adapter.
**Suggested fix**: Standardize redirect construction (prefer request-aware origin where available) and reuse the shared route adapter consistently.

### 🟡 Temporary debug script remains in the working tree, `scripts/tmp-clean-authz-http.ts`
**Problem**: A `tmp-*` script is included among untracked changes.
**Why it matters**: Temporary scripts are easy to commit accidentally and can confuse maintainers about supported tooling.
**Suggested fix**: Remove it from the changeset if not needed, or rename/document it if intentionally kept.
